# Blueprint CMS (BPCMS)

Flat file CMS inspired by Kirby. PHP >= 8.4, namespace `Blueprint\` → `src/`. Design decisions are logged in `building_history.log` (append to it when making architectural changes). User documentation lives in `docs/` (`guides`, `reference`, `examples`), a content folder rendered by `site/templates/default.php` (styles in `public/assets/css/docs.css`, fonts Inter from rsms.me and Fira Code (no ligatures) from jsDelivr, scripts in `public/assets/js/docs.js` (anchors, toc, copy buttons, mobile menu, header search: Fuse.js from jsDelivr over the links of `#docs-menu`), code highlighting in `public/assets/js/highlight.js` with speed-highlight from jsDelivr and an own php grammar): pages are `name.md` (a folder with `page.md` only if it has subpages), front matter `title` and `sort` (menu order), links are site paths (`/guides/content#files`, folders with a trailing `/`), no links to project files – update it together with code changes.

## Commands

- `composer install`
- `composer test` (Pest, tests in `tests/`; they only use fixture projects in `tests/fixtures/`, never the project content)
- `composer serve` → dev server on http://localhost:8000 (`public/index.php` is the front controller)
- `composer panel:build` (Vue + Vite in `panel/` → `public/panel/`, committed by `composer release`), `composer panel:dev` (vite on :5173/panel/, proxies the API to :8000)
- `composer release [version]` (`bin/release`, no dependencies): suggests the next version after the latest `v*` tag (`0.1.0-alpha.1` first, pre-releases `alpha` → `beta` → `rc`) or takes your own (checked as semver, must be greater), builds the panel, writes the version into `composer.json`, `panel/package.json` and the lock files, commits only these files and `public/panel/` and creates the annotated tag `v{version}`; nothing is pushed. Refuses when these files have uncommitted changes.
- `bin/blueprint user:create <email> [role]`, `user:password <email>`, `user:list`, `content:uids`, `media:clear`, `public:setup [--force]`, `setup` (`Setup`, interactive with adhocore/cli's `Interactor`, refuses without a tty: `public:setup`, `site/` from `site_template/` if missing, `content/home.md` if there is no home page, first admin + other users, `setup:gitignore` (missing lines of `.gitignore_template` in the package root, with their comments), `setup:composer` (`blueprint public:setup` as post-install/update script, a `serve` script unless any script runs `php -S`), `content.optimizeImages`/`content.allowPHP` into a new `config/config.php`, printed if it exists), `repl` (PsySH, `$app`/`$site`, `Blueprint\` classes aliased without namespace) (`Cli`: every php file in `src/cli/commands/`, plugins' `cli/` and `site/cli/` returns `["command", "description", "usage"?, "run" => fn (array $args)]`, run may return an int exit code; site commands override plugin and core ones)

GitHub Actions (`.github/workflows/`): `ci.yml` runs the tests on PHP 8.4–8.5 and builds the panel; `docs.yml` renders `docs/` with `static:build _site --base-path=…` (from `actions/configure-pages`) and deploys it to GitHub Pages (https://pstaender.github.io/blueprint-cms/, repo https://github.com/pstaender/blueprint-cms).

## Architecture

- `public/index.php` → `App::create(Config::load(PROJECT_DIR . "/config"))->run()`, `public/.htaccess` rewrites to it for Apache
- Installed as a composer package (`pstaender/blueprintcms`): `vendor/bin/blueprint` (composer's proxy sets `$_composer_autoload_path`, `PROJECT_DIR` is the root package's path from `InstalledVersions`), `public:setup` (`PublicFolder`) copies the package's `public/index.php`, `.htaccess` and built `panel/` into the website's `public/` (existing `index.php`/`.htaccess` only with `--force`, the panel is always replaced). Core code finds its own files via `__DIR__`, the website's via `App::projectDir()`. `.gitattributes` keeps the docs project (`config/`, `site/`, `docs/`, `public/assets/`), panel sources, tests and dev files out of the package.
- `Config` – defaults (`debug`, `panel`, `contentFolder`, `siteFolder`, `content.optimizeImages`, `content.allowPHP` (php files in the content folder are ignored unless `true` or `["edit" => [roles or user emails/names]]`, `Page::phpFilesEnabled()`, `User::canEditPhpFiles()`; pages with a php file can only be changed/moved/deleted in the panel by admins and these users, `User::canChangePhpPages()`, `canChange` in page summaries; their type can't be changed), `csp` (opt-in, default `false`): `true` = `Config::CSP_DEFAULTS`, an array of directive => sources is merged over them, for the `Content-Security-Policy` of rendered pages, nonce via `csp_nonce()`; the panel has its own `Panel::CSP`) < `site/config/config[.{host}].php` < `config/config[.{host}].php`. Config files return arrays (lambdas allowed).
- `App` – singleton (`App::instance()`), wraps a Dumbo router with a catch-all route. `/panel*` goes to `Panel` if `panel` is enabled (the website never depends on the panel). Pages with a php file get every method, other pages and files only GET/HEAD/OPTIONS (OPTIONS → 204, others → 405, `Allow` header). Pages:
  1. `content/redirects.json` (`{"301": {"from": "to"}}`)
  2. `Site::find($path)` resolves the slug path to a `Page`, else 404 (`site/templates/404.php`)
  3. canonical url redirect (301): pages with published children end with `/`, others don't; `/home` → `/`
  4. render: the page's own php file (`page.php` / `{slug}.php`) if present – its output is the response, unless it returns an array, which is merged into the page data (only while rendering) and rendered with the template. Otherwise `site/templates/{template}.php` → `page.php` → `default.php` → `src/views/default.php`.
  5. no page → a file of the parent page (`/blog/cover.jpg`), only if `File::isUsed()` (filename in the data of its page or of its single file subpages, or `file://uid` / `blog/cover.jpg` / `/blog/cover.jpg` anywhere) or a user is logged in; served with safe headers (only images/media/pdf/text inline, other types as `application/octet-stream` attachments, `nosniff`, CSP sandbox). Relative file links (`Page::relativeFile()`: single file pages use the files of their folder page) and `page://uid`/`file://uid` links in markdown are resolved by `File::resolveUrls()` (textarea and writer field values, `md()`).
- `Page` – a folder with `page.json`/`page.md`/`page.content.md`/`page.php`, or a `{slug}.md`/`{slug}.php` file. `01_blog` → num 1, slug `blog`; leading `.` = draft (only visible for a logged in user). Folder pages win over file pages with the same slug. Data merge order: `page.json` < `page.md` front matter < `page.content.md` (as `content`). `type` (data, default `page`) chooses blueprint + template, `template` (data, `Page::template()`) overrides only the template. Writes: `update`, `changeStatus`, `changeNum`, `changeSlug`, `changeParent` (moves into a folder page or the root), `changeType`, `changeContentFormat` (`json` | `md` | `json+md`, file pages become folders), `create`, `delete`; every write fills the hidden `SystemFields` (`uid`, `createdAt`, `modifiedAt`, also for files and users; the site only gets the dates; markdown pages don't store them, their dates come from the file's mtime), structural changes refresh `App::site()`.
- `File` – other files in a page folder (not `.md`/`.php`/content/meta/hidden), data in `{filename}.json` (`uid`, `template` → `files/{template}.yml`, `accept` rules on upload). `replace($contents)` keeps filename, uid and data.
- `Uid` – 16 char ids for pages, files, users; references `page://uid`, `file://uid`, `user://uid` (pickers store them, `FieldValue::toPages/toFiles/toUsers` resolve them and legacy paths/filenames).
- `Block`/`Layout`/`LayoutColumn` – blocks/layout field content (Kirby format). Fieldsets from `blocks/{type}.yml` (core in `src/blueprints/blocks`), normalized into the field's `fieldsets`; rendering via `App::renderSnippet("blocks/{type}")` → `site/templates/snippets/blocks/` or `src/views/blocks/`.
- `Data` – read-only, raw (unescaped) data: maps become `Data` (object/array access, missing keys → `null`), lists stay arrays.
- `ContentFile` – reads json and markdown with yaml front matter (body → `content`).
- `Site` – `content/site.json` + root pages. `User` – `content/users.json`, roles `user`, `admin` (core blueprint, `isAdmin()`; the first/only user is admin) + user blueprints, only admins see/create/edit/delete other users and change roles, password changes in the panel need the current user's password unless admin, current user from the session (`$_SESSION["blueprint.user"]` = uid). `Passkey` – WebAuthn login for the panel (ES256/RS256, user verification required), stored in the user's `passkeys`; the browser sends the public key (`getPublicKey()`), so there is no CBOR/attestation parsing, logins are checked with `openssl_verify`.
- `Model` – base class of models: `site/models/{Class}.php` / plugins' `models/` (loaded by `Models::load()` at `App::create`), name = class name in camelCase, blueprint `collections/{name}` (`panel: true` → panel "Collections", `softDelete: true`, `files: false`, `perPage` (default 10), `searchableFields`). Records are a json list in `content/{collection}.json` (`COLLECTION` const, default plural of the name), written under `flock`, system fields, refs `{name}://{uid}` (`Models::resolve()`, `record()`), trash `content/.trash/{collection}/{uid}.json` (files in `files/` next to it), files `content/.database_files/{collection}/{uid}_{filename}` (both folders reserved in `Page::scan`). The docs' page ratings: `site/models/PageRating.php`, endpoint `docs/rating/page.php` (`hidden: true` pages aren't in the docs menu), the layout draws the `thumbs-up`/`thumbs-down` panel icons from `panel/src/icons.json`.
- `Plugin` – folders in `site/plugins/` with `index.php` or `{folder}.php` (only that file is loaded, at `App::create`, alphabetically; it requires its other php code from anywhere). Plugins can have `blueprints/`, `templates/` (snippets, partials, 404) and `cli/` like the site: `App::siteDirs($folder)` = site first, then plugins, then core (`Blueprint::roots()`, templates, snippets, partials, `Cli`). `site/plugins/static-site-generator`: `bin/blueprint static:build [folder] [--clear-existing-target-folder]` renders listed + unlisted pages via `App::request()` into `static/` (url → `{path}/index.html`), used files, `404.html`, redirects as meta refresh pages, `public/` without `index.php`/`panel/`; `--base-path=/sub` prefixes root-relative `href`/`src`/`action`/`poster` and redirects for hosting in a subfolder.
- `Redirect` exception – thrown by `redirect()`, turned into a response by `App`.
- `Blueprint` – `site/blueprints/{name}.{yml,yaml,php}`, falls back to core blueprints in `src/blueprints/`. Names are paths: `pages/article`, `site`, `users/editor`, `custom-fields/seo`. `Page::blueprint()`: `pages/{template}` → blueprint with `default: true` → `pages/default`; `User::blueprint()`: `users/{role}` (role defaults to `user`) → `users/user` → `users/default`; `Site::blueprint()`: `site`. Also `fields()`, `field()`, `tabs()`, `defaults()`, `validate($data)`, `toArray()`.
- `BlueprintNormalizer` – raw props → tabs → columns → fields (`Blueprint::DEFAULT_FIELDS`: pages and the site get a `subpages` pagelist unless they have a pagelist or `subpages: false`; `false` removes any (inherited) field; Kirby v6 style: root `fields` are definitions referenced by name from tabs/columns when a layout exists; `fields: true` in a tab/column = all unused definitions; sections → fields; groups spliced; `extends`; string shortcuts; blocks/layout `fieldsets` and `layouts`). Invalid fields become `info` error fields instead of exceptions.
- `Field` – a blueprint field definition (`name`, `type`, props, `validate()`).
- `FieldValue` – field methods of models (`HasFields` trait on `Page`, `Site`, `User`, `Values`): `$page->createdAt()` is formatted + escaped by field type when echoed; other calls go to Carbon/Collection/Stringable (string results are wrapped again, so they stay escaped). Raw values stay in `data()`. Model methods win over field names, use `_url()` (a leading underscore is stripped) or `field("url")`. `Values` = structure rows / object fields.
- `ImageOptimizer` – AVIF versions of used content images in `public/media/images/{hash}/{filename}.avif` (GD or Imagick, adapters `GdImageFile`/`ImagickImage`), helpers `optimized_content_image()`/`optimized_content_images()`; config `content.optimizeImages` applies it to every rendered page.
- Global helpers in `src/helpers.php`: `page()`, `site()`, `user()`, `md()` (Markdown Extra only with config `markdown.extra`, `App::markdown()`; inline html escaped unless `html: true`, unsafe link schemes → `#`, `Field::isSafeUrl()`), `esc()`, `dump()`/`dd()` (symfony/var-dumper, html theme in `Dumper`), `redirect()`, `partial()` (returns the html of `site/templates/partials/{name}.php` or an absolute php path, throws if missing), `snippet()`/`endsnippet()`/`slot()`/`endslot()` (Kirby style, `site/templates/snippets/`, `Snippet`/`Slots`), `static_file_url()` (mtime from `public/`).
- Templates get `$page` and `$site`; field methods are already escaped (`esc()` doesn't double-escape them), raw `data()` must be `esc()`ed, `md()` for markdown.

- `Panel` – serves `public/panel/index.html` for all `/panel/*` urls and the REST API under `/panel/api` (own regex routing, see `Panel::ROUTES`; page ids are slug paths with `/`, also in panel urls; subresources start with `~`: `/pages/blog/~children`, `/pages/blog/~files/cover.jpg`). Session login (`Session`, `$_SESSION["blueprint.user"]`) + `X-CSRF-Token` for changes; validation by blueprint (422). Writes via `Page::update/changeStatus/changeNum/create/delete`, `Site::update`, `User::create/update/delete`. Docs: `docs/reference/panel-api.md`.
- Panel frontend (`panel/src`): `App.vue` (login / sidebar + view), `views/` (Site, Page, File, Users, User, Collection + Record: records of models, nested route `/models/{name}/{uid}`), `components/ModelForm.vue` (tabs → columns), `FieldList.vue` (field grid + `when`), `FieldInput.vue` (one native input per field type), `fields/` (structure, object, pickers, page/file lists, blocks, layout, `WriterField.vue`: markdown editor with tiny-markdown-editor (TinyMDE) and an own toolbar of native buttons, links pages via `PageSelectDialog.vue` (browse/search, `page://uid`) and files via `FileSelectDialog.vue`), `Sidebar.vue` (only the page tree scrolls, "Pages" collapsible, state in localStorage), `PageTree.vue` (sidebar tree: highlights the open page and expands its parents, context menu: move, status), `PageItems.vue` (page lists: sort, add, bulk status/move/delete), `ParentSelect.vue`, `PageIcon.vue` + `icons.js`/`icons.json` (also listed in the docs by `docs/reference/panel-icons/page.php`; blueprint `icon`: a panel icon name (Kirby's names, hand-written paths, `{d, fill}` for filled parts), a `data:image/…` URI (css mask) or text/emoji; a page's `icon` field (`fields/IconField.vue`, icon picker `IconSelectDialog.vue`, svg uploads < 50 KB inline, `Field::isValidIcon`) overrides it, no default house for the home page; pages with a php file default to the `php` icon (Skill Icons logo, filled with evenodd cut-outs)), `CodeEditor.vue` (CodeMirror 6, loaded on demand: the php editor of a page's php file in `PageView.vue`, `PUT /pages/{id}/~php` checks the syntax with `Page::phpSyntaxError()` (`token_get_all(TOKEN_PARSE)`), 422 → "Save anyway" with `force`), `ContextMenu.vue` (right click / ⋯ menu, used by the file list), `editing.js` (edit state: sends only changed fields + `modifiedAt`/`original` for the 409 conflict check, `Panel::checkConflicts`), `sortable.js` (native drag & drop), `files.js` (file store + uploads as raw request body), `api.js` (fetch client + session state), `passkeys.js` (WebAuthn in the browser: login, add passkey; passkeys are listed and deleted in `UserView.vue`). Colors are css variables in `styles.css` (`--color-accent` = black primary by default, for checkboxes, radios and switches, which are drawn with css (`appearance: none`) so they look the same in every browser). Keep form fields simple and native.

## Guidelines

Modern PHP, keep it simple, flat class structure, camelCase, self-explaining names, comments only where code isn't obvious, English. Breaking changes are fine until a stable release.

## Not implemented yet

Translations, site files, panel customizations by plugins, controllers, routes in `site/`, panel permissions for models, sqlite/postgres.
